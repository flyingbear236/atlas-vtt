# Как написать рулсет для ATLAS v0.4

Создай обычный файл `scout.toml` в UTF-8 и добавляй блоки ниже по порядку. Вместе они образуют один рулсет с Разведчицей, Дозорным, оружием и настойкой. Когда закончишь, загрузи его в ATLAS через **Настройки кампании → Рулсеты и файлы → Добавить → Загрузить файлы**. Проверь предпросмотр, примени файл и размести героев через **Персонажи → Добавить → Существующий персонаж**.

## Характеристики и HP

```toml
[stat.will]
name = "Воля"
type = "integer"
default = 14
bonus = { formula = "floor((value - 10) / 2)" }

[stat.guard]
name = "Защита"
default = { formula = "10 + stat.will.bonus" }

[stat.hp]
name = "Здоровье"
default = { formula = "18 + stat.will" }
resource = true

[stat.motto]
name = "Девиз"
default = "Сначала разведка"

[stat.ready]
name = "Готовность"
default = true
```

`default` обязателен. При константе это исходное значение для персонажа, пока тот не получил собственный `base`. При формуле ATLAS пересчитывает базу по зависимостям и показывает её в листе без поля ввода. `type` можно опустить. Поддерживаются целое число, строка и логическое значение.

- `stat.will.base` читает базу Воли. `stat.will` читает эффективную Волю с применёнными эффектами.
- В формуле поля `bonus` переменная `value` читает эффективную Волю. Следующая формула обращается к результату через `stat.will.bonus`. При Воле 14 бонус равен 2, а Защита — 12.
- `resource = true` добавляет `stat.hp.current`. `stat.hp` означает эффективный максимум, `stat.hp.base` — исходный максимум, `stat.hp.current` — текущее сохраняемое значение. При отсутствии сохранённого `current` начальное значение берётся из базы ресурса. Пересчёт максимума не поднимает и не обрезает уже существующий `current`. Лечение, урон и пределы задавай явно в действиях.

## Эффект от экипировки

```toml
[effect.amulet_will]
name = "Сила амулета"
target = "stat.will"
formula = "target + 2"
priority = 1
stack = "unique"

[object.amulet]
name = "Амулет Воли"
effects = ["effect.amulet_will"]
```

Надетый амулет добавляет к эффективной Воле 2. В `effect.formula` слово `target` означает промежуточное значение поля из `effect.target`. Эффект пересчитывается от исходного значения при каждом изменении состояния. Снятие амулета убирает его бонус и пересчитывает зависимые поля.

При `unique` два амулета дают те же +2. При `repeat`, которое действует по умолчанию, оба экземпляра дадут суммарно +4. Эффекты применяются по возрастанию `priority`, по умолчанию 0. При равенстве ATLAS сортирует по ID эффекта, затем по ID источника. Предупреждение о совпадающем приоритете особенно важно, если один эффект прибавляет число, а второй делит результат.

## Проверка с кубиком и двумя исходами

```toml
[action.check.resolve]
name = "Проверка решимости"
roll = "1d20 + stat.will.bonus"
var.dc = "12"
var.margin = "roll - var.dc"
success = "roll >= var.dc && stat.ready"
message = "Сложность {var.dc} · запас {var.margin}"

[action.check.resolve.on.success]
message = "Разведчица собралась с духом."

[action.check.resolve.on.fail]
message = "Разведчица колеблется."
```

`1d20` бросает один двадцатигранник на сервере. `roll` в последующих выражениях означает итог с эффектами и вычисляется один раз за исполнение. `var.*` живут внутри одного исполнения и рассчитываются по мере обращения. Для сообщения используй подстановки вроде `{var.dc}` и `{roll}`.

`success` возвращает логическое значение. При истине применяется `on.success`, при лжи — `on.fail`. Основное `message` выполняется независимо от результата. В выражениях доступны арифметика, скобки, сравнения, `&&`, `||`, `!`, функции `floor()` и `dice()`. Для произвольных названий вложенных полей используй кавычки в TOML, например `"класс защиты" = 12`, и такое же цитирование при обращении к полю в выражении.

## Оружие, цель и урон

```toml
[action.weapon]
name = "Действия копья"

[action.weapon.hit]
name = "Попадание копьём"
target = "select(character)"
roll = "1d20 + stat.will.bonus"
success = "roll >= target.stat.guard"

[action.weapon.damage]
name = "Урон копьём"
target = "select(character)"
roll = "dice(source.damage) + stat.will.bonus"
apply = { path = "target.stat.hp.current", formula = "value - roll" }
message = "Копьё наносит {roll} урона"

[effect.steady_hand]
target = "action.weapon.hit.roll"
formula = "target + 1"
scope = "source"
when = "source.style == 'balanced'"

[effect.find_gap]
target = "action.weapon.hit.roll"
priority = 1
when = "action.target.stat.hp.current < 20"
formula = "target + 2"

[effect.practice]
target = ["action.weapon.hit.roll", "action.check.resolve.roll"]
priority = -1
formula = "target + 1"

[object.spear]
name = "Копьё дозора"
style = "balanced"
damage = "1d6"
actions = ["action.weapon"]
effects = ["effect.steady_hand"]
```

`action.weapon` — группа. Копьё предоставляет оба дочерних действия, и у каждого отдельная кнопка. Попадание проверяет цель и завершает своё исполнение. Для нанесения урона ведущий или игрок нажимает отдельное действие.

`source` указывает на конкретный экземпляр копья, давший действие. `dice(source.damage)` читает строку `"1d6"` из его полей. У двух копий будут отдельные кнопки. `scope = "source"` даёт +1 только от того экипированного экземпляра, с которым выполняется попадание. В `when` можно проверить свойство источника. В эффекте игровая цель доступна по `action.target`. У `effect.find_gap` +2 срабатывает по цели с текущими HP ниже 20, если эффект выдан персонажу. Массив в `effect.practice.target` добавляет +1 к попаданию и проверке решимости. Каждый адрес указывается целиком.

`apply.path` называет поле для сохранения, а `value` в `apply.formula` означает его старое значение. Если было 20 HP и итог броска равен 7, сервер сохраняет 13. Запись в вычисляемое поле или базу с формульным `default` отклоняется. Для условной записи помести `apply` в `on.success` или `on.fail`.

Для `select(character)` можно выбрать **Без цели**. Независимый бросок всё равно запишется в журнал. Проверка, сообщение или запись, которым нужна отсутствующая цель, будут пропущены. Ошибка чтения поля у уже выбранной цели прерывает действие.

## Осмотр, лечение и заряд предмета

```toml
[action.inspect]
name = "Осмотреть настойку"
target = "select(object)"
message = "{target.name} · {target.notes.label} · порций {target.stock.uses}"

[action.recover]
name = "Перевязаться"
target = "self"
apply = { path = "target.stat.hp.current", formula = "value + 2" }
message = "Восстановлено 2 HP."

[action.drink]
name = "Выпить настойку"
target = "source"
success = "source.stock.uses > 0"
message = "Проверка флакона {source.name}"

[action.drink.on.success]
apply = { path = "target.stock.uses", formula = "value - 1" }
message = "Потрачена одна порция."

[action.drink.on.fail]
message = "Флакон пуст."

[object.tonic]
name = "Настойка"
notes.label = "Горькая"
actions = ["action.drink"]
```

`select(object)` предлагает предметы из инвентарей персонажей, которыми можно управлять. Осмотр читает название и маркировку из определения флакона, число порций — из экземпляра. Операции с одной только строкой `message` не создают бросок.

`self` автоматически выбирает самого исполнителя. `source` как селектор цели выбирает предмет, который предоставил кнопку. Поэтому `target.stock.uses` у **Выпить настойку** меняет порции именно этого флакона. Действие **Перевязаться** отдельно показывает простой пример лечения. Для лимита лечения можно использовать формулу `value + 2` с отдельным условием `success = "target.stat.hp.current + 2 <= target.stat.hp"` и поместить запись в `on.success`. В основной части оставь, например, `message = "Проверка перевязки."`, чтобы действие оставалось исполняемым.

`actor` в формулах даёт доступ к исполнителю и его полям, например `actor.profile.callsign`. `stat.*` — быстрый доступ к статам исполнителя. `target` в обычном действии — выбранная игровая цель. Вложенные поля вроде `notes.label`, `stock.uses` и `style` имеют тот смысл, который ты задашь выражениями.

## Персонажи, экипировка и сохранение

```toml
[character.scout]
name = "Разведчица"
profile.callsign = "Сойка"
stat.will.base = 14
stat.hp.current = 21
actions = ["action.check.resolve", "action.inspect", "action.recover"]
effects = ["effect.find_gap", "effect.practice"]

[[character.scout.inventory]]
id = "charm-a"
object = "object.amulet"
equipped = true

[[character.scout.inventory]]
id = "spear-a"
object = "object.spear"
equipped = true

[[character.scout.inventory]]
id = "tonic-a"
object = "object.tonic"
equipped = true
stock.uses = 2

[character.sentry]
name = "Дозорный"
stat.hp.current = 18
```

`character.actions` и `character.effects` — прямые назначения персонажа. Экипировка добавляет к ним действия и эффекты предметов с `equipped = true`. У предмета обязателен уникальный ID в пределах этого инвентаря. Например, для второго флакона укажи `id = "tonic-b"` и ту же ссылку `object = "object.tonic"`. Снятие предмета отключает его вклад и сохраняет поля экземпляра.

При первой загрузке `[character.scout]` создаёт сохранённого персонажа. После этого его значения и инвентарь меняются в кампании. Правка стартовой записи с тем же ID сама по себе не сбрасывает его состояние. Для переноса текущих персонажей вместе с правилами экспортируй ZIP и импортируй его в новую кампанию.

## Проверка файла перед игрой

```toml
[stat.a]
default = { formula = "stat.b + 1" }

[stat.b]
default = { formula = "stat.a + 1" }
```

Это отдельный пример ошибки. ATLAS отклонит цикл, потому что ни одна формула не может быть вычислена первой. Предпросмотр также покажет дубли ID, ссылки на отсутствующие определения и ошибки типов в выражениях.

Для v0.4 заголовок `schema_version` не нужен. Можно держать все пять сущностей в одном TOML или разложить их по файлам. При загрузке связанных файлов добавляй их одним набором. ID определяется полным путём, поэтому `action.weapon.hit` и `action.check.hit` — разные действия. Для исполняемого действия требуется хотя бы одно из `roll`, `message` и `apply`. Для группы требуется исполняемый потомок. Данные вне зарезервированных полей остаются пользовательскими данными. Например, таблица `{ formula = "..." }` внутри произвольного поля предмета сама по себе ничего не вычисляет.
