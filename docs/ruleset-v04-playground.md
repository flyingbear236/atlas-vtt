# Как проверить Ruleset v0.4 в ATLAS

Возьми [ruleset-v04-playground.toml](../examples/definitions/ruleset-v04-playground.toml). Он добавляет Испытателя с предметами, Манекен и Стража. Для проверки достаточно пустой сцены.

## 1. Новая кампания и загрузка

1. Запусти ATLAS как обычно. Если нужен отдельный сервер с чистыми данными, из папки проекта выполни команды PowerShell ниже.

   ```powershell
   $testData = "data-ruleset-test-" + (Get-Date -Format 'yyyyMMdd-HHmmss')
   go run . -addr 127.0.0.1:8081 -data $testData
   ```

   При отдельном запуске открой `http://127.0.0.1:8081`.

2. Создай новую кампанию, войди на сцену как ГМ и открой **Настройки кампании → Рулсеты и файлы → Добавить → Загрузить файлы**. Выбери TOML. В окне проверки файл должен быть выбран, а **Применить** — доступно. После применения библиотека сообщит **Импорт завершён**.
3. Открой **Персонажи → Добавить → Существующий персонаж**. По очереди выбери **Испытатель**, **Манекен**, **Страж** и нажми **Разместить** для каждого. Токены могут появиться в одном месте. Перетащи их в стороны или выбирай персонажей через список.

## 2. База, формулы и экипировка

Открой лист **Испытателя** из списка. Раздел **Инвентарь** находится под вкладками листа.

| Что сделать | Что увидеть |
| --- | --- |
| Посмотреть лист при двух надетых кольцах | Сила **20**, базовое **16**, поле `bonus` **5**. Атлетика **5**, Мастерство **3**, Фокус **5**, у Сигнала поле `gain` **7**, Здоровье **24 / 40**. У Девиза текст, у «Готов к проверке» значение **Да**. |
| Снять `ring-b` | Сила **18**, `bonus` и Атлетика **4**, Здоровье **24 / 38**. Фокус всё ещё **5**. |
| Снять и `ring-a` | Сила **16**, `bonus` и Атлетика **3**, Здоровье **24 / 36**, Фокус **2**. |
| Надеть оба кольца обратно, поменять базовое значение Силы с **16** на **14** | Сила **18**, `bonus` и Атлетика **4**, Здоровье **24 / 38**. У Мастерства и максимума Здоровья поля ввода базы нет. |
| Вернуть Силу **16**, поменять базу Уровня с **6** на **9** | Мастерство станет **4**. Верни Уровень **6** перед следующими шагами. |

Кольца складывают силу через `repeat`. Фокус от обоих колец учитывается единожды через `unique`. Усиление сигнала равно `floor((10 + 5) / 2) = 7`, потому что сначала срабатывает эффект с приоритетом 1. Текущие **24 HP** переживают все изменения максимума.

## 3. Действия, выбор цели и последствия

Открой вкладку **Действия** Испытателя. Итоги ищи в правой панели и в **⚄ Журнале**. Следующие значения рассчитаны для начальных параметров и двух надетых колец.

| Что нажать | Что увидеть |
| --- | --- |
| **Сводка испытателя** | Строку с позывным **Маяк**, силой **16 → 20**, бонусом **5**, фокусом **5**, усилением **7** и HP **24/40**. Кубиков и итога броска у записи нет. |
| **Проверка навыка** | `1d20` и итог на **8** больше грани. Атлетика даёт +5, Мастерство через эффект даёт +3. |
| **Пробный выпад** → **Манекен** → **Выполнить** | Итог **15**, **DC 13 · запас 2**, **Успех**. HP Манекена меняется **30 → 27**. |
| **Пробный выпад** → **Страж** | Та же **15**, сообщение о провале, HP Стража **36 / 36**. |
| **Пробный выпад** → **Без цели** | Итог **15** и строка **DC 13 · запас 2**. Проверка успеха и изменение HP пропущены. |
| **Восстановить 2 HP** | Срабатывает на Испытателя без выбора цели. Его HP меняется **24 → 26**. Запись содержит сообщение и изменение ресурса. |

У Манекена защита **14**, у Стража **16**. Исходный результат выпада **12**, общий эффект тренировки добавляет **3**. В его записи нет выпавших граней, поскольку выражение `roll` состоит из константы.

## 4. Несколько источников одного действия

В группе **Удар оружием** проверь **Попадание** и **Урон**. У каждой карточки есть кнопки для `rune-a`, `rune-b`, `plain` и `dagger`. Кнопки клинков с одинаковым именем различаются по ID экземпляра.

| «Попадание» | Ожидаемый итог |
| --- | --- |
| Любой рунический клинок по Манекену | Грань `d20` **+ 11**. Сила +5, владение воинским оружием +3, эффект именно этого клинка +2, открытая стойка Манекена +1. |
| Обычный клинок `plain` по Манекену | Грань **+ 9**. Бонус рунического клинка отсутствует. |
| Кинжал `dagger` по Манекену | Грань **+ 6**. Условие воинского оружия ложно. |
| Рунический клинок без цели | Грань **+ 10**. Эффект стойки и проверка попадания пропущены. |

1. Сними `rune-a`. Его кнопки пропадут, `rune-b` останется и по-прежнему даст свои +2. Затем экипируй `rune-a` обратно.
2. После **Попадания** посмотри HP цели. Он меняется только после отдельного **Урона**.
3. Выполни **Урон** клинком по Манекену. Журнал показывает грань `d8`, итог **грань + 5** и вычитание этой суммы из текущих HP. У кинжала будет `d4`. Если выбрать **Без цели**, бросок остаётся в журнале, а HP никого не меняется.
4. Для сравнения введи в **Быстром броске** `2d6 + 1d4 + 3`. Должны появиться две грани `d6`, одна `d4` и итог, равный их сумме плюс 3.

## 5. Цель-предмет и сохраняемые поля экземпляра

1. Нажми **Осмотр предмета**, выбери **Сигнальную катушку · coil**. Появится сообщение **ЛАТУНЬ · заряды 2**, без броска. Маркировка приходит из определения предмета, число зарядов — из его экземпляра.
2. Нажми **Пуск катушки** дважды по очереди. Цель подставляется автоматически. В журнале появятся изменения **2 → 1**, затем **1 → 0**. На третий пуск будет **Провал** и **Катушка разряжена**, значение останется 0.
3. Осмотри катушку снова и проверь **заряды 0**. Сними её. **Пуск катушки** исчезнет, а осмотр по-прежнему доступен. Надень катушку обратно и проверь, что заряды всё ещё 0.
4. **Калибровка предмета** на катушке даёт **10** и **Успех**, поскольку её `dc` равен 8. Выбери для той же калибровки обычный клинок. У клинка нет поля `dc`, поэтому должна появиться ошибка выполнения.

## 6. Отображение игроку и сохранение

- **Индикатор HP.** В **Настройках кампании → Индикаторы характеристик** добавь **Здоровье**, выбери **Число** и сохрани. Выполни ещё один **Урон** по Манекену. Число у его токена должно обновиться вместе с листом.
- **Права игрока.** Зайди по приглашению в отдельном профиле браузера. Как ГМ, через меню токена **Настроить управление** выдай игроку Испытателя. Игрок сможет выполнить действия Испытателя и выбрать видимого Манекена. Лист Манекена игроку открыть для управления не удастся. При осмотре предмета игрок увидит свою катушку `coil`. Катушка Стража `coil-guard` в список не попадёт. Если ГМ скроет Стража через свойства токена, он исчезнет из списка целей игрока.
- **Переподключение.** Запиши HP Манекена, HP Испытателя, заряды катушки и экипировку. Обнови страницу и вернись на сцену. Значения и записи журнала должны восстановиться. Выполненные действия при открытии сцены второй раз не применяются.
- **ZIP.** В **Рулсетах и файлах** нажми **Экспорт ZIP → Скачать ZIP**. В другой новой кампании выбери **Импорт ZIP**, проверь выбранные файлы и примени. Размести персонажей из списка снова. В чарлистах должны быть записанные HP, заряды, экипировка и формулы из исходного TOML. Журнал и токены сцены проверяются переподключением к исходной кампании.

## 7. Проверка редактора и ошибки правил

- Открой загруженный TOML через **Пробный выпад** в списке действий файла. Поменяй у `effect.signal_reduce` приоритет на **0**, сохрани через **Проверить изменения → Применить**. Усиление сигнала станет **10**. Сначала будет `floor(10 / 2)`, затем +5. Поставь приоритет **1**. Предпросмотр должен предупредить о совпадающих приоритетах, а результат вернётся к **7** благодаря порядку по ID эффекта. Верни исходный приоритет **2**.
- Для проверки отказа загрузи отдельный файл `bad-cycle.toml` с содержимым ниже. Предпросмотр должен показать цикл, применение будет заблокировано. Закрой окно импорта и проверь, что текущий рулсет продолжает работать.

  ```toml
  [stat.bad_a]
  default = { formula = "stat.bad_b + 1" }

  [stat.bad_b]
  default = { formula = "stat.bad_a + 1" }
  ```
