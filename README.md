# Атлас — прототип VTT

Самостоятельная реализация по `desc.txt`: Go-сервер, браузерный JavaScript без сборщика, Canvas 2D и WebSocket. React/Vue и Go в ТЗ были вариантами, а не обязательным стеком. Зависимости: Gorilla WebSocket и отдельный libvips для обработки изображений.

## Запуск

Нужны Go 1.26+ и libvips. Для Windows x64 из папки проекта сначала выполните `./scripts/install-vips.ps1` (официальный libvips 8.18.6, SHA-256 проверяется). Затем:

```powershell
go run .
```

Открыть **http://127.0.0.1:8080**. Создать стол, открыть сцену и загрузить свою карту PNG/JPEG.

Можно собрать исполняемый файл со встроенным интерфейсом. libvips остаётся внешней зависимостью:

```powershell
go build -o atlas.exe .
.\atlas.exe
```

Для игроков в локальной сети:

```powershell
.\atlas.exe -addr 0.0.0.0:8080
```

Ведущий открывает `http://IP-адрес-компьютера:8080`, затем нажимает «Пригласить». Ссылка содержит приглашение игрока. Для доступа с другого компьютера порт 8080 должен быть доступен в локальной сети. Для размещения в интернете нужен HTTPS reverse proxy, который поддерживает WebSocket.

## Что работает

- Создание кампании с несколькими сценами, ведущим и несколькими игроками. Ведущий создаёт, переименовывает, публикует и удаляет сцены; игрок видит только опубликованные. Клиент подписан максимум на одну сцену.
- У сцены собственные логические размеры и до двух этажей. У каждого этажа есть непрозрачность, отдельная видимость снизу, обычные visual layers, ровно один Token Layer и одна прямоугольная игровая область. Token Layer можно переставлять среди visual layers: например, крона дерева рисуется над токеном, а мебель под ним.
- Загруженное на сцену изображение становится обычным `SceneElement`: его можно двигать, менять размер и угол, переносить между слоями, дублировать без копии файла и менять порядок отрисовки. Один Campaign Asset используется любым числом элементов.
- Визуальное PNG/JPEG до 256 МиБ, 150 миллионов пикселей и 32768 px по стороне автоматически получает обычный bitmap до 1024 px либо tiled LOD для более крупного изображения. Повернутый tiled-элемент запрашивает только тайлы, реально пересекающие viewport, и один соседний ряд. Исходное изображение не отправляется в браузер.
- Токены привязаны к Token Layer своего этажа. Player не может выйти за Walkable Bounds; GM может административно поставить токен снаружи и увидит красную отметку. Авторитетный Transition проверяет права, исходный этаж, область перехода и точку назначения.
- Campaign Asset Store хранит metadata и файлы отдельно от экземпляров на сцене. Поддержаны политики `keep`/`reclaimable` и обнаружение orphan без немедленного удаления файла.
- Загрузка изображений токенов; сервер готовит вариант до 512 px. Создание, изменение, удаление токенов, цвет, размер, имя, назначение игрока и скрытие от игроков.
- Своя камера у каждого участника: перетаскивание фона, масштаб колесом или кнопками, вписывание карты, включение сетки. У Player есть активный принадлежащий ему токен: он серверно определяет текущий этаж. Выбор своего токена на Canvas либо в списке делает его активным; выбор в списке также центрирует камеру. Последний активный токен и камера запоминаются только этим браузером и заново проверяются сервером после reconnect. Стартовый масштаб ограничен так, чтобы region loading захватывал несколько spatial cells, а не всю большую карту. Alt + перетаскивание позволяет двигать камеру поверх токена. Сетка визуальная, без привязки.
- Перемещение разрешённых токенов: до 20 сетевых обновлений в секунду при перетаскивании и обязательная финальная позиция при отпускании. Свой токен рисуется сразу, удалённые координаты интерполируются.
- Авторитетный сервер: игрок не может менять свойства, двигать чужие/скрытые токены, выбирать `SceneElement` или загружать ассеты. Player не видит редактор этажей/слоёв и Walkable Layer. В списке навигации он видит все свои нескрытые токены, включая далёкие и находящиеся на другом этаже, но список не раскрывает их asset ID и не загружает изображения. Скрытые токены и элементы вне `Scene.Bounds` не включаются в region snapshot; доступ к изображениям проверяется с учётом активного токена и текущего compositing этажей.
- Последовательные ревизии. При пропуске события запрашивается актуальный snapshot текущей загруженной области. Устаревшие события игнорируются. Одновременно допускается максимум один `view` request: если камера уехала дальше до ответа, после snapshot запрашивается только последнее актуальное положение, поэтому быстрый pan не создаёт очередь устаревших region snapshots. Автопереподключение с паузой 1–10 секунд и повторная синхронизация. Кэш изображений сохраняется.
- Локальное хранение в `data/`: оригиналы, тайлы, метаданные, кампании и ключи доступа. Позиции coalesce в RAM и сохраняются общим flush примерно раз в 5 секунд; ACK финальной позиции и realtime не ждут диск. При аварийном завершении могут потеряться последние несколько секунд движения. Создание/удаление, свойства, permissions и Scene CRUD записываются до ACK и одновременно flush'ят накопленные позиции. Ctrl+C сохраняет pending state и закрывает соединения.
- Region loading сначала выбирает участвующие в compositing этажи, затем viewport и элементы, и лишь затем их asset metadata/байты. Этаж с нулевым effective alpha не вызывает сетевых запросов или декодирования. До шести загрузок одновременно; ненужные запросы отменяются при движении камеры.
- IndexedDB: LRU-кэш байтов с лимитом 128 МБ и ограниченной очередью ожидающих записей. RAM-бюджет изображений выбирается автоматически по грубому `navigator.deviceMemory`: 64 МБ для устройств до 4 GiB, 128 МБ для среднего/неизвестного класса и 256 МБ для 16+ GiB, если браузер сообщает такое значение. В диагностике можно локально переопределить бюджет на Auto / 64 / 128 / 256 / 512 МБ; 512 МБ никогда не выбираются автоматически. 8 МБ общего RAM-бюджета зарезервированы под подготовленную графику токенов, остальное доступно ImageBitmap. При большом видимом наборе разрешение декодирования снижается, чтобы набор помещался одновременно. При перегрузке необязательная запись в IndexedDB пропускается. Отказ IndexedDB/квоты не мешает работе. HTTP-ответы ассетов имеют `private, immutable` и срок год.
- Диагностика: число реально нарисованных кадров, время отрисовки, оценка RAM изображений, объём IndexedDB, байты изображений и WebSocket, попадания в дисковый кэш, активные загрузки и ошибки. В покое 0 кадров/с — нормальный режим перерисовки по изменениям.
- Для экспериментов: переключение постоянного рендера, переподключение, очистка кэша и добавление 100 токенов за раз (защитный лимит сцены — 100000).

## Управление

1. Создайте стол. На главной кампании выберите сцену или создайте новую.
2. Ведущий может переименовать, опубликовать, скрыть или удалить сцену. Новая сцена скрыта от игроков.
3. Откройте сцену. Разделы «Сцена», «Объекты» и «Участники» переключаются в верхней панели; левая панель меняет содержимое, регулируется по ширине и может быть свёрнута.
4. В разделе «Сцена» ведущий задаёт размеры, создаёт этажи и слои, загружает изображения и управляет деревом. Перетаскивайте элементы на Canvas за рамку и маркеры; Shift при угловом resize разрешает свободные пропорции.
5. В разделе «Объекты» нажмите `+` или загрузите изображение токена.
6. Выберите токен на карте/в списке, задайте свойства и сохраните.
7. Пригласите игрока. Когда он войдёт, назначьте его в поле «Управление». Кнопка «К сценам» возвращает к Campaign Home, где доступны создание/редактирование сцен и «Выйти из кампании».

`F` над активным холстом — показать всю карту, `Escape` — снять выбор, `Delete` — удалить выбранный токен (ведущий). На главной странице доступны сохранённые входы в сессии. Ключ ведущего хранится в браузере; приглашение не даёт прав ведущего. Потеря localStorage означает потерю доступа из этого браузера, поэтому сохраняйте профиль браузера и резервную копию `data/`.

## Проверки

```powershell
go test -v ./...
go vet ./...
```

Интеграционные тесты используют настоящий HTTP/WebSocket сервер: права и синхронизация токенов, floors/layers/elements, transforms, transitions, region loading, скрытые слои и assets, persistence/reconnect, asset retention, уровни и крайние тайлы.

Дополнительная проверка в настоящем Chrome или Edge:

```powershell
$env:ATLAS_CHROME='C:\Program Files\Google\Chrome\Application\chrome.exe'
$env:ATLAS_SCREENSHOT='C:\projects\my-game\prototype.png'
go test -run TestBrowser -v
```

Она создаёт временный профиль и временную сессию, проверяет навигацию сцены и сворачивание левой панели, загружает тестовую карту через обычный upload endpoint, изменяет токен, переподключается, проверяет ошибки JavaScript и сохраняет снимок. Без `ATLAS_CHROME` браузерная проверка пропускается.

## Границы прототипа

Нет тумана войны, стен, освещения, бросков, Actor/листов персонажей, Asset Library, физического asset GC, аудио/видео, истории/отмены, офлайн-редактирования и дельта-журнала восстановления. При открытии и восстановлении клиент получает metadata сцены, затем актуальный snapshot только своего region. Full-scene fallback отсутствует: старые варианты протокола не поддерживаются, потому что у прототипа пока нет выпущенных клиентов. Одновременное перемещение одного токена или элемента разрешается последним принятым сервером событием; блокировки захвата нет.

Это прототип для доверенной игровой группы: приглашения постоянные, отдельной системы аккаунтов, отзыва ключей, ограничения частоты HTTP-запросов и очистки серверного хранилища нет. Только тот, у кого есть ключ ведущего, управляет сессией. Уже показанное игроку изображение нельзя отозвать из его браузера последующим скрытием.

RAM-индикатор учитывает ImageBitmap и подготовленную графику токенов, а не весь процесс браузера и не GPU. Лимит IndexedDB не управляет собственным HTTP-кэшем браузера. Загрузка пишется прямо во временный файл; тайлы создаёт отдельный процесс libvips. Одновременно обрабатывается одно изображение. Для interlaced PNG и progressive JPEG сама библиотека всё ещё может потреблять сотни МиБ; жёсткого ограничения RSS нет. Цели 60 FPS / 200 мс из ТЗ не объявляются достигнутыми: нагрузку 100–1000 объектов, большие карты и несколько компьютеров следует измерять на целевом оборудовании. Основной интерфейс рассчитан на настольный браузер.

## Надёжность во второй итерации

- Изменение свойств — отдельный `properties` patch: в нём нет координат. Устаревший full-token `update` protocol удалён. Игрок может двигать токен, пока ведущий меняет его имя, цвет или размер.
- Финальная позиция — LWW-команда `final`. У неё отдельный browser stream `client + seq`: сервер меняет RAM, рассылает позицию и отвечает сразу, а позицию вместе с receipt сохраняет ближайший общий flush. Если процесс аварийно завершился до flush, следующий position seq принимается после restart без блокировки очереди.
- Reliable business-команды используют отдельный Outbox в `sessionStorage`, сохраняются через временный файл, `Sync` и замену до ACK и остаются строго последовательными. Position Outbox тоже повторяет неподтверждённый `final` после обычного reconnect. Запоздалое промежуточное движение того же position stream не откатывает уже подтверждённый финал.
- Пока нет подтверждения, финальная позиция остаётся на экране как локальное ожидание. Отклонение по правам возвращает серверную позицию и показывает причину.
- Черновики свойств хранятся отдельно от снимков сервера, по токенам и полям. Обновления участников, перемещения и переподключение не стирают ввод. Подтверждение старой формы не стирает более новый ввод.
- Неверный ключ, отсутствующая сессия и нарушение последовательности business-команд останавливают автоматические повторы с понятной ошибкой. Ошибки чтения/структуры `sessions.json` прерывают запуск без перезаписи сохранения. Singleton `Scene.Map` отсутствует: карта всегда остаётся обычным `SceneElement`. При запуске текущие visual layers получают явный `kind`, каждому этажу добавляются Token/Walkable layers, а токены привязываются к своему Token Layer.
- RAM-кэш удерживает видимый набор без взаимного вытеснения. Размеры выбираются отдельно для каждого изображения по его размеру на экране, без увеличения исходника, с сохранением пропорций. При переполнении уменьшается разрешение нужных изображений; видимые ассеты имеют приоритет над соседними тайлами. Возраст сам по себе больше не удаляет ImageBitmap: невидимые записи остаются в RAM, пока хватает бюджета. После пересечения high watermark невидимые записи выселяются по LRU до примерно 85% лимита, чтобы не возникала постоянная очистка около границы. При окончательном eviction вызывается `ImageBitmap.close()`. Временные буферы декодера и основной Canvas в этот бюджет не входят.

Дополнительные тесты: движение игрока + переименование ведущим → финал → переподключение → перезапуск → проверка имени и позиции; повтор команды после потери ACK; позднее промежуточное движение; отказ диска и повтор; повреждённое сохранение; штатная остановка через тот же контекст отмены, который использует обработчик Ctrl+C. Само нажатие клавиш в консоли тест не имитирует.

Chrome/Edge дополнительно проверяют несохранённый ввод, новые координаты списка, отсутствие координат в патче свойств, прекращение повторов при ошибке входа, ручной RAM override и уменьшение кэша с 128 до 64 МиБ на 80 перекрывающихся изображениях 512×509 при большом масштабе. Модульный browser scenario отдельно проверяет Auto-профили, fallback без `deviceMemory`, отсутствие age-only eviction, LRU, защиту `wanted` и hysteresis.

## Оставшиеся ограничения

Atlas рассчитан на небольшую доверенную группу. Rate limiting, квоты пользователей/сессий/диска и защита публичного хостинга намеренно не реализованы. Запекание visual layers, анимации, коллизии, полноценный FOV, свет и интерактивные SceneElement пока отсутствуют. Остаются общий mutex сервера, полная запись JSON и полный обход IndexedDB при записи. Клиент использует единый region-state contract: при открытии Scene сначала получает только metadata и entry point, затем запрашивает viewport с bounded prefetch; далёкие tokens и их asset metadata клиенту не передаются. Сервер поддерживает неперсистентный uniform-grid spatial index и фильтрует realtime по загруженному региону. Capability/fallback-веток старого протокола нет. Проведены прежние локальные замеры до 2000 токенов, а spatial index отдельно проверен на 50000 токенов; многочасовые игры и несколько физических компьютеров ещё не проверены.

Не закрывайте вкладку до подтверждения: `sessionStorage` не гарантирует сохранение очереди после закрытия вкладки. Несохранённый черновик формы живёт в памяти страницы. Одновременные изменения одного и того же свойства или перемещения ведущего и владельца разрешаются порядком приёма сервером. Гарантия записи предполагает исправный диск и файловую систему; резервная копия `data/` по-прежнему нужна.

Файлы: `main.go` — Campaign persistence и HTTP/WS lifecycle; `scenes.go` — snapshots, region loading и доступ к ассетам; `scene_content.go` — модель floors/layers/elements/transitions; `scene_commands.go` — их команды; `reliable.go` — reliable transport и токены; `web/scene-content.js` — Canvas-геометрия и рендер; `web/scene-tree.js` — дерево сцены; `web/app.js` — интеграция; `scene_content_test.go` — новые серверные проверки; `browser_test.go`, `browser_scenarios_test.go` — Chrome/Edge через DevTools.

## Профилирование третьей итерации

Методика и команды: [profiling/README.md](profiling/README.md). Итоги и пределы: [profiling/REPORT.md](profiling/REPORT.md).

Добавлены пространственный индекс токенов и кэш готовой графики в пределах прежних 64 МБ. При дальнем масштабе подписи скрыты, кроме выбранного токена; остальные появляются при диаметре от 24 px. Нарезка перенесена в libvips; Go больше не хранит полную декодированную карту. Формат тайлов сохранён. В текущей версии лимит карты поднят до 150 млн пикселей, а лимит исходного файла — до 256 МиБ; лимит стороны остаётся 32768 px. Незавершённый специальный обработчик interlaced PNG удалён.

Основные файлы: `web/rendering.js`, `web/token-renderer.js`, `image_pipeline.go`, `image_process_windows.go`, `image_process_other.go`; проверки — `image_pipeline_test.go`, `image_processing_test.go`, `profile*_test.go`.

libvips ищется через ATLAS_VIPS, затем в vips/bin рядом с atlas.exe, в локальной .deps и в PATH. Для переноса на другой ПК копируйте весь каталог vips-dev-8.18 под именем vips рядом с atlas.exe, включая DLL и лицензии. Для Linux/macOS установите libvips из пакетов системы. Без него сохранённые сцены открываются, а новая загрузка выдаёт понятную ошибку. Официальные пакеты: https://www.libvips.org/install.html .

Полный финальный повтор нагрузочных замеров не завершён: работа остановлена по запросу пользователя. Текущие результаты и ограничения записаны в profiling/REPORT.md.
