# Задание для Sol 5.6 medium: ограниченные оптимизации Atlas

## Цель

Уменьшить повторную работу в spatial index, редакторе и render path до Milestone 3–5. Пользовательских функций не добавлять. Это отдельная задача от ATLAS_MILESTONES_3_5.md: не реализовывать здесь bake, Fix Rotation или новый representation pipeline.

Сначала прочитать AGENTS.md и восстановить актуальное состояние по коду. Предыдущее ревью относится к восстановленному snapshot; последующие изменения могли уже исправить часть замечаний. Реализованное не переделывать.

Работать последовательно по этапам ниже. До каждого изменения проверить воспроизводимость проблемы. Если место уже эффективно или цена оптимизации не оправдана, оставить его и кратко объяснить. Не добавлять универсальный framework, ECS или новую renderer architecture.

## A. Ограничить spatial index крупных SceneElements

Точки входа: scenes.go — elementCells/addElement/removeElement/queryElements; scene_content.go — transform validation и геометрия.

Сейчас описанная окружность может превращать даже длинное узкое изображение в большую квадратную область индекса. Индексация всех ячеек зависит от площади transform и не имеет отдельного лимита.

1. Вычислять AABB повёрнутого прямоугольника. Угол, центр и transform convention взять из существующего renderer. Консервативный AABB не должен терять пересечения на границе.
2. До выделения массива вычислять число ячеек и сравнивать с централизованным лимитом на элемент. В качестве стартовой гипотезы допустимо 256 cells, затем проверить стоимость на реальных картах. Это tuning parameter, не лимит пользовательского размера объекта.
3. Если превышен лимит, хранить ID в отдельном наборе oversized elements, а не заполнять сотни тысяч buckets. queryElements объединяет кандидатов grid и oversized, выполняет финальную геометрическую проверку и не возвращает дубликатов.
4. Корректно поддержать обычный ↔ oversized при resize/rotate, move, delete, rebuild и rollback. Не сломать asset reference counts и floor-aware filtering.
5. Не вводить R-tree до измеренной необходимости. Линейный перебор небольшого oversized-набора приемлем; сценарий большого количества oversized также измерить и честно описать предел.

Тесты: тонкий длинный объект; произвольный угол; отрицательные координаты; 1 000 000 × 1 000 000 transform без гигантского allocations; запрос на границе; переход между двумя способами хранения; удаление и rebuild. Проверять ограничение структуры и выдачу, а не только скорость.

Замер: allocations/bytes и время add/move/query до/после на безопасных размерах. Не выполнять заведомо опасный максимальный кейс на старой реализации; для него достаточно расчёта числа ячеек, затем запуска исправленной реализации.

## B. Не перестраивать DOM дерева на каждый transform

Точки входа: web/app.js — element event handler/renderPanels; web/scene-tree.js — update.

Разделить transform-only и структурные изменения. При elementTransform обновлять scene state, необходимые spatial/geometry caches и dirty Canvas. Обновлять только поля выбранного элемента, которым это действительно нужно, сохраняя несохранённый ввод.

Полный rebuild дерева не нужен при x/y/rotation/size change, если структура и отображаемые строки от этого не зависят. Create/delete/name/layer/order/visibility обновляют необходимые строки или дерево по текущему простому механизму. Не вводить виртуальный DOM.

Проверки: входящий drag 20 Hz на сцене с сотнями элементов; DOM-узел строки сохраняет identity на transform; дерево корректно меняется при переносе между слоями; форма не стирает draft; selection не теряется. Замерить количество tree rebuild, время обработки события и frame time.

## C. Убрать повторную сортировку render stack и добавить bitmap culling

Точки входа: web/scene-content.js, web/app.js. Сначала измерить текущую стоимость с 100/1000 elements и несколькими visual Layers.

Кэшировать распределение по слоям и детерминированный z-order. Инвалидировать при create/delete/layer/zOrder или snapshot/Scene switch. Не инвалидировать весь порядок на каждый move/revision. Кэш не должен удерживать устаревшие объекты после immutable replacement transform event: хранить ID либо явно обновлять ссылки.

Opacity/visibility/Floor order должны сразу отражаться в render, даже если не требуют повторной сортировки элементов. Кэш ограничен активным scene-local state и очищается при переключении Scene.

Перед requestImage обычного bitmap проверить пересечение viewport; bounded prefetch выделить явно. Уже загруженный spatial region не приравнивать к visible viewport. Учитывать rotation и текущий локальный drag transform. Для tiled сохранить существующее отсечение тайлов.

Не вводить второй клиентский spatial index без необходимости: списки слоёв и дешёвое AABB culling — достаточный первый шаг.

Проверки: A → B без старых элементов; новый zOrder виден сразу; движение использует актуальный transform; Floor alpha=0 не вызывает requests; bitmap за prefetch не запрашивается; возвращение камеры переиспользует кэш. Pixel/render-order тест проверяет Tokens внутри своего Layer, а не отдельным верхним проходом.

## D. Пропустить redundant activeToken request

Точка входа: activatePlayerToken и pointerdown.

Только если focus=false, activeTokenId совпадает и Floor соответствует подтверждённому сервером текущему view, выполнить локальный selection/drag без отправки activeToken и полного snapshot.

При pending optimistic switch не считать локальные значения подтверждёнными. Проверить текущий механизм подтверждения/отказа. Если его нет, добавить минимальное различение confirmed/pending или консервативно выполнять fast path только после snapshot; при отказе восстановить authoritative view через существующий sync.

Выбор другого токена и focus из панели оставить рабочими. Тестировать повторный drag активного токена, переключение на соседний Floor и ownership/hide/delete race. Не исправлять попутно весь протокол locators; отдельные найденные проблемы перечислить.

## E. Ограничить вспомогательные cache metadata

Точки входа: diskTouches и nativeSizes в web/app.js.

Проверить lifetime этих maps. Установить централизованный разумный cap или связать записи с существующим lifecycle; metadata eviction не должен закрывать нужный bitmap или удалять серверный Asset. Использовать простой ограниченный Map, без таймера на каждый ресурс.

diskTouches хранит время последнего успешного обновления IndexedDB used, а не каждого чтения. Учесть завершение/abort транзакции; не подавлять обновления used навсегда частыми обращениями. Очистка кэша сбрасывает связанную metadata bookkeeping.

Тесты: больше cap различных ключей; горячий ресурс с частыми обращениями всё равно периодически обновляет used; отказ IndexedDB не ломает rendering. Измерить количество записей, а не объявлять точную RAM по размеру map.

## F. Только при подтверждённой выгоде: облегчить token position index update

При move внутри прежних cells не удалять и создавать buckets заново. Asset reference counts не обновлять, если asset, floor и hidden неизменны.

Прежде убедиться, что query использует актуальные координаты, а не копию старого Token. Preserve revision/index counters, transitions между Floors, no-op, delete и rollback.

Сравнить move benchmark для нескольких токенов и массовых обновлений. Если gain мал, а код заметно сложнее, этот этап пропустить с измерениями. Это low priority.

## Что в эту задачу не входит

- Перенос JSON persistence вне глобального mutex: отдельная итерация после измерения lock hold time, с отдельным дизайном durable commits/rollback.
- Изменение opacity semantics, Floors/Transitions model и reliable ACK guarantees.
- Bake, sparse manifests, derived assets, animation support, GC и новые пользовательские функции.
- Увеличение cache limits, удаление сохранений или перезапись чужих изменений.
- Полное переписывание плотных JS-файлов ради форматирования.

Идеи для дальнейших milestones уже включены в ATLAS_MILESTONES_3_5.md: reuse по recipe hash, filter halo для тайлов, bounded jobs, conditional commit и immutable representations. Не дублировать их реализацию здесь. Удержание старого LOD до готовности нового можно рассмотреть отдельно только при воспроизводимом мигании и с учётом общего RAM-бюджета.

## Проверки и сдача

Сохранить baseline до изменений, не путать snapshot из /dev/null с обратимым diff. Применять UTF-8 явно; не прогонять смешанные исходники через неявную Windows-кодировку.

После каждого этапа — релевантные тесты. В конце gofmt изменённых Go-файлов, go test -v ./..., go vet ./... и доступный Chrome/Edge сценарий. Не повторять полный suite после каждого мелкого изменения без причины.

Браузерные measurements проводить на одинаковых fixtures/viewport/DPR/cache state. Минимум: плотная сцена, drag элемента, pan/zoom, повторное открытие. Report frame time и load/decode/rebuild counts; 0 FPS в idle нормален для event-driven render.

Краткое саморевью: memory lifetime, invalidation, stale references, permissions, scene switching, reliable retries. Исправить регрессии текущего патча.

Финал: изменённые файлы; таблица до/после с параметрами нагрузки; пройденные и пропущенные проверки; оставшиеся ограничения. Обновить snapshot по актуальному AGENTS.md. Не заявлять прирост производительности там, где есть только расчёт сложности.
